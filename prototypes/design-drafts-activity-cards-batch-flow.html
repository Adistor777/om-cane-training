Design drafts

Two decisions on this page: A. how activity cards should look, and B. the batch result flow (select students → tick results → CSV). Everything is drawn with the app's real tokens — paper, ink, one green accent. The batch screens are tappable: try selecting faces and ticking results.

A · Activity cards — three directions

Current cards are a title + two tags. The real information a teacher needs at this point: which stage comes next, has this child done it before, is there a demo. Each variant bets on a different one of those.

A1 · Current (baseline)

What ships today. Calm, but every card looks equally important — no sense that Stage 1 leads to Stage 2, and "5 saved" is the only progress signal.

A2 · Stage ladderRecommended

Numbers the stages and draws the thread between them — the curriculum's motivate → skill → independence progression becomes visible. A filled number = "this stage has results". Cheapest to build, strongest wayfinding.

A3 · Media-forward

Leads with the demo-video frame — instantly scannable, good for training new teachers. But it doubles card height, needs a thumbnail for every activity (three are still missing), and decorates a list the teacher visits dozens of times a day.

B · Batch result flow — the one design

Replaces the single-child picker entirely (a solo session is a batch of one). Three moments: pick the roster → run & tick → one CSV row per child. Adding a student mid-flow drops them into the roster already selected, marked NEW. The checkbox is the result; tapping a row opens optional detail so the mastery scale and counts survive.

3 · What lands in the CSV

Each child in the batch = one row, same file the existing export produces. Ticked-only saves keep the sheet honest: unticked children get "not yet" rows only if the teacher opened their detail — otherwise no row (absence ≠ failure).
